# OfferMate 实现计划（docs/plan）

本目录是 **可执行、可评判** 的分步实现计划，作为完成度评判的唯一依据。
上层产品/架构规划见 [`../项目规划.md`](../项目规划.md)。

## 已锁定的关键决策

| 项 | 决策 |
|----|------|
| 应用形态 | 完全端侧，无自建后端 |
| AI 密钥 | BYOK（用户自填），加密存储于本地 |
| 首选大模型 | **DeepSeek**（`AiClient` 首个适配目标，OpenAI 兼容接口） |
| AI 框架 | **自研轻量会话/记忆层 + `AiClient` 抽象**（不引入重型 Agent 框架），详见 [`ai-framework.md`](./ai-framework.md) |
| 端侧记忆 | 三层记忆（工作/情景/语义）+ 多职业档案 + 事实取代机制，支持方向切换与多简历，详见 [`memory.md`](./memory.md) |
| 核心能力 | 分析用户分享**链接**中的面经 → 抽题 → 简历相关性筛选 → 生成答案 |
| 内容来源 | 用户分享/粘贴的**单篇链接**（非批量爬虫） |
| 开发方式 | **测试先行**：核心能力先在 `src/test` 下通过测试，再接入真实链接/UI |
| 语言/UI | Kotlin + Jetpack Compose (Material 3)（绿地迁移） |

## 测试先行原则（硬性要求）

> "在进行链接读取实现前，必须先在测试中通过，即核心能力先在 test 下进行测试。"

- **核心能力 = AI 分析流水线（抽题/相关性/作答）+ 内容解析（HTML→正文、正文→题目）**。
- 这些逻辑必须先以 **JVM 单元测试（`app/src/test`）** 覆盖，使用**离线夹具**（录制的 LLM 响应 JSON、保存的页面 HTML），**不依赖网络、不依赖真机、不依赖真实 Key**。
- 只有单测通过后，才实现"真实链接读取（WebView/网络）"与"真实 DeepSeek 调用"这类需要设备/网络的部分（用 instrumented 测试或手动验证）。

## 阶段总览与完成定义（Definition of Done）

| 阶段 | 名称 | 完成定义（可评判） |
|------|------|--------------------|
| P0 | 工程脚手架与工具链 | 项目切到 Kotlin+Compose，能编译、能跑一个空单测 |
| P1 | 领域模型 + AI 分析流水线（测试先行） | 抽题/相关性/作答三步逻辑单测全绿（用夹具） |
| P2 | 内容读取（测试先行） | HTML→正文 解析单测全绿；牛客夹具能提取正文；小红书按结论处理 |
| P3 | 本地存储 + 设置(BYOK) | Room/DataStore 单测通过；能加密保存/读取 DeepSeek Key |
| P4 | UI 与刷题机制 | 导入→简历→题目→刷题 全流程可用；答案隐藏/自评生效 |
| P5 | 集成、真实链接、打磨 | 端到端跑通真实链接+真实 DeepSeek；异常兜底完善 |

详细任务、交付物与验收标准见：
- [`roadmap.md`](./roadmap.md) — 分步任务清单（评判用）

## 进度约定

- 每个任务在 `roadmap.md` 中以 `- [ ]` / `- [x]` 标记。
- 一个阶段的所有"验收标准"满足后，方可进入下一阶段。
- P1、P2 未达"测试全绿"前，**不**开始其真实网络/设备实现。
