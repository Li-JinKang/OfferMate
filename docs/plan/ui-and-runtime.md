# UI 结构与后台运行设计

## 1. 导航结构（精简）

底部 **3 个 Tab**（设置不单独占位，收进"我的"）：

| Tab | 名称 | 内容 |
|-----|------|------|
| 1 | 导入（首页） | 分享/粘贴链接、读取预览、手动粘贴正文兜底、历史导入列表、触发分析 |
| 2 | 题库 & 刷题 | 题目列表、刷题卡片、复习/筛选、（后续）追问会话 |
| 3 | 我的 | 简历、职业档案切换、（后续）记忆管理、**设置**（DeepSeek Key / 模型 / 阈值 / 隐私 / 免责） |

二级/系统页：读取预览、题目详情、刷题页、简历导入、职业档案、记忆管理（后续）、设置、小红书 WebView 登录页、分析结果/错误反馈。

## 2. 后台运行与任务调度（重点需求）

**场景**：用户通勤时看到面经帖子 → 分享链接进 App → 可立即离开 → 午饭时回来查看已整理好的题目。

**核心要求**：分享后即可退出 App，链接读取 + AI 分析在后台可靠完成、结果可随时查看。

### 2.1 设计
- **分享即入队、立即可退出**：接收 `ACTION_SEND` 链接后，立刻落库一条 `ImportedPost(status=PENDING)` 并把任务提交给 `WorkManager`，UI 立即可返回/关闭，不阻塞用户。
- **WorkManager 链式任务**：`ReadWork`（读取正文）→ `AnalyzeWork`（抽题→相关性→作答）。
  - 约束 `requiredNetworkType = CONNECTED`；失败按指数退避重试。
  - 进程被系统杀死/设备重启后，WorkManager 会恢复未完成任务，保证"午饭时结果已在"。
- **前台服务 + 通知**：分析属长耗时联网任务，用 expedited work + `setForeground` 展示进度通知（"读取中 / 分析中"），规避后台网络与 Doze 限制。
- **完成通知**：分析完成后发本地通知——"《帖子标题》已整理，产出 N 道相关题"，点击直达题目列表。
- **结果持久化**：全部写入 Room，随时查看；**无后端，任务全在设备本地**。
- **失败可恢复**：读取失败 → 状态转 `NEEDS_MANUAL_INPUT`，在导入列表标注并提供"手动粘贴正文"；分析失败 → 可重试。

### 2.2 导入任务状态机
```
PENDING → READING → (READ_FAILED → NEEDS_MANUAL_INPUT)
                  → ANALYZING → (DONE | ANALYZE_FAILED→可重试)
```

### 2.3 前置校验
- 入队前校验 BYOK 的 DeepSeek Key：无 Key 则提示去"我的 → 设置"，不入队。

### 2.4 约束与注意
- Android 后台执行限制（Doze / App Standby）：用 WorkManager + 前台服务保证可靠性。
- 通知权限：Android 13+ 需申请 `POST_NOTIFICATIONS`。
- 成本：一次分析可能多次调用 DeepSeek，需节流、缓存（同链接不重复分析）、并向用户提示消耗。
